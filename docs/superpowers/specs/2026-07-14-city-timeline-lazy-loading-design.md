# Ленивая загрузка хронологии городов

## Цель

Исключить построение хронологии посещений из первоначальной загрузки страниц со списком всех посещённых городов и списком городов региона. Данные должны запрашиваться только при первом открытии соответствующего модального окна.

## Область изменений

Изменение распространяется на:

- `/city/all/list`;
- `/region/<region_id>/list`;
- модальные окна хронологии на этих страницах;
- два новых API-эндпоинта;
- общую клиентскую логику `timeline_modal.js`.

Карты городов и регионов, существующие фильтры списка, сортировка и пагинация не меняются.

## API

### Общая хронология

`GET /api/city/timeline`

Эндпоинт возвращает все сохранённые посещения текущего пользователя. Необязательный query-параметр `country` содержит ISO 3166-1 alpha-2 код страны. При наличии параметра возвращаются только посещения городов выбранной страны, при отсутствии параметра — полная хронология.

### Хронология региона

`GET /api/region/<region_id>/city_timeline`

Эндпоинт возвращает хронологию текущего пользователя в указанном регионе: непосещённые города, посещения с датой и посещения без даты.

### Доступ и ошибки

Оба эндпоинта доступны только авторизованному пользователю и определяют пользователя исключительно по `request.user`. Клиент не передаёт идентификатор пользователя.

- Неавторизованный запрос получает `401 Unauthorized`.
- Неизвестный код страны получает `404 Not Found`.
- Неизвестный идентификатор региона получает `404 Not Found`.
- Неподдерживаемый HTTP-метод получает типизированный `405 Method Not Allowed` с `Allow: GET`.
- Корректный запрос без элементов получает `200 OK` с пустыми массивами.

### Формат ответа

Оба эндпоинта возвращают единый JSON-контракт:

```json
{
  "items": [
    {
      "city_title": "Казань",
      "date_label": "14.07.2026",
      "status": "visited",
      "year": 2026,
      "is_first_visited": true
    }
  ],
  "years": [2026, 2025]
}
```

Для элементов без года поле `year` имеет значение `null`. `is_first_visited` равно `true` только у первого посещённого элемента и `false` у остальных элементов. `status` принимает значения `visited` и `unvisited`.

Порядок сохраняет текущее поведение:

- общая хронология: посещения с датой от новых к старым, затем посещения без даты по названию города;
- хронология региона: непосещённые города по названию, посещения с датой от новых к старым, затем посещения без даты по названию;
- повторные посещения одного города остаются отдельными элементами;
- годы уникальны и отсортированы по убыванию.

## Серверная архитектура

ORM-логику построения обеих хронологий следует вынести из page-view в отдельный сервис. Сервис принимает идентификатор текущего пользователя и область выборки: необязательную страну для общей хронологии либо обязательный регион для региональной.

Page-view больше не выполняют timeline-запросы и не добавляют `city_timeline_items`, `city_timeline_years`, `region_timeline_items` или `region_timeline_years` в контекст. Они передают шаблону только уже доступные `country_code` и `region_id`, необходимые для формирования URL API.

API-обработчики реализуются только как django-modern-rest `Controller` с DMR Router и типизированными msgspec-схемами. Они отвечают за аутентификацию, разрешение страны или региона, вызов сервиса и сериализацию результата. Бизнес-порядок элементов не дублируется между API и page-view.

## Шаблоны и клиент

Модальные окна остаются в исходном HTML, чтобы сохранить текущую доступность и нативное поведение `<dialog>`, но вместо элементов хронологии содержат:

- URL API в data-атрибуте;
- скрытый контейнер фильтра годов;
- контейнер содержимого;
- начальное состояние загрузки;
- шаблон или данные, необходимые общему JavaScript для отображения пустого результата и ошибки.

При нажатии кнопки JavaScript сразу открывает модальное окно и, если данные ещё не загружены, выполняет `fetch` указанного URL.

- Во время запроса отображается состояние загрузки.
- После успешного ответа JavaScript строит фильтры годов и элементы хронологии, затем выполняет существующее позиционирование к первому посещённому элементу.
- Данные вставляются безопасно через DOM API и `textContent`, без интерполяции API-значений в `innerHTML`.
- После успешной загрузки результат остаётся в DOM, повторные открытия не выполняют новый запрос.
- После ошибки отображается понятное сообщение и кнопка повторной попытки. Ошибка не помечает данные как загруженные, поэтому повторная попытка выполняет новый запрос.
- Существующая фильтрация по одному или нескольким годам, сброс фильтра и прокрутка сохраняются.

Для общей страницы URL содержит `?country=<country_code>` только при активном фильтре страны. Остальные параметры текущей страницы в API не передаются. Для страницы региона URL всегда содержит идентификатор текущего региона.

## Проверка

Backend-тесты должны подтвердить:

- обязательную аутентификацию обоих API;
- изоляцию данных пользователей;
- полную общую хронологию без `country`;
- ограничение общей хронологии выбранной страной;
- `404` для неизвестной страны и региона;
- область региона, порядок элементов, повторные посещения, пустой результат и список годов;
- отсутствие построения и timeline-данных в контексте первоначальных page-view.

Frontend-тесты должны подтвердить:

- отсутствие запроса до открытия окна;
- единственный запрос при первом успешном открытии;
- отсутствие повторного запроса после успешной загрузки;
- передачу URL из шаблона без его самостоятельного изменения JavaScript-кодом;
- отображение данных и сохранение фильтрации по годам;
- состояние ошибки и новый запрос при повторной попытке.

После целевых тестов необходимо выполнить полный набор затронутых backend- и frontend-тестов, frontend-сборку и настроенные линтеры изменённых файлов.
