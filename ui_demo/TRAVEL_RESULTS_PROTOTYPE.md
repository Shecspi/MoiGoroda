# Прототип «Итоги путешествий»

Throwaway UI-прототип отвечает на вопрос: какая подача превращает историю посещений в понятные личные итоги, а не в ещё одну страницу статистики?

## Запуск

```bash
make run-travel-results-prototype
```

После запуска открыть <http://localhost:8000/ui-demo/travel-results-prototype/?variant=B&scenario=rich> под учётной записью суперпользователя. Маршрут доступен только при `DEBUG=True`.

Вариант меняется параметром `variant=A|B|C`, состояние данных — параметром `scenario=rich|quiet|lifetime|compare|teaser|expired|studio`. Стрелки клавиатуры переключают варианты.

## Варианты

- `A · История по главам`: один смысловой акцент на экран, последовательное прохождение.
- `B · Журнальный разворот`: итоги как личный ежегодник, который можно прочитать целиком.
- `C · Панель исследователя`: обзор и инструменты видны одновременно, сценарий ближе к рабочему разделу.

## Проверяемые гипотезы

- Последовательность из четырёх глав понятна без объяснений и не перегружает экран.
- Редкий год звучит доброжелательно и не создаёт ложного ощущения неудачи.
- Итоги отличаются от личной статистики за счёт наблюдений, маршрута и финального материала.
- Персональный тизер объясняет ценность, не блокируя существующую бесплатную статистику.
- Одна карточка и серия собираются из одинакового ограниченного набора настроек.
- Пять направлений шаблонов достаточно различимы, а фотодневник не использует фотографии без явного выбора.
- После окончания подписки понятна разница между доступной исходной историей и скрытым снимком.
- Все варианты сохраняют рабочую иерархию на узком и широком экране.

## Текущее состояние проверки

- Выбран базовый вариант: `B · Журнальный разворот`.
- В B нужно сохранить эмоциональную подачу, возможность увидеть весь итог сразу и структуру разворота, связывающую карту, текст и показатели.
- Заимствования из A и C не требуются: дальнейшая проработка сосредоточена на B.
- По итогам текущего ручного просмотра вариант B предварительно принят без дополнительных изменений.
- Реализованы насыщенный год, редкий год, вся история с посещениями без даты, сравнение с нулевой базой и равным результатом, тизер, закрытый архив и студия публикации.
- Добавлено явное состояние фотодневника без фотографий и после ручного выбора трёх фиктивных кадров.
- При реализации редактор был сокращён до готового направления, формата, темы, акцента, типа вывода, блоков и маркировки. Свободное перемещение элементов намеренно отсутствует.
- UI-аудит подтверждён: действия, статусы, панели, метрики, списки, формы и переключатели собраны из компонентов daisyUI с префиксом `dui-`. Собственная разметка оставлена только внутри схематической карты, журнального направления и экспортируемых карточек как части проверяемого визуального результата.
- Production-сборка frontend и существующие проверки `ui_demo` проходят.
- Остаточный риск: отдельный формальный прогон всех сценариев на реальном мобильном устройстве не зафиксирован.

## После проверки

Перенести выбранную структуру B и зафиксированные продуктовые правила в implementation issue. Сам прототип сохранить в throwaway-ветке как первичный источник; в main переносить только подтверждённые решения, переписанные как production-код.
