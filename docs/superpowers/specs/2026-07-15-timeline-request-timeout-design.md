# Таймаут загрузки хронологии

## Цель

Не оставлять модальное окно хронологии в состоянии `loading`, если сетевой запрос не завершается, и позволять пользователю повторить загрузку без перезагрузки страницы.

## Изменение

В `frontend/js/entries/timeline_modal.js` добавляется таймаут запроса длительностью 10 секунд:

- перед каждым `fetch` создаётся новый `AbortController`;
- `signal` controller передаётся в `fetch`;
- через 10 секунд таймер вызывает `abort()`;
- отклонённый после abort запрос обрабатывается существующей веткой ошибки, которая устанавливает состояние `error`;
- таймер очищается в `finally` при любом результате запроса;
- Retry после ошибки создаёт независимый controller и запускает новый запрос.

Машина состояний, UI-тексты и серверный API не меняются.

## Проверка

В `frontend/js/entries/timeline_modal.test.js` добавляется тест с fake timers. Первый mock-запрос остаётся незавершённым до abort, после 10 секунд проверяются abort signal и состояние `error`; затем Retry получает успешный ответ и переводит модальное окно в `loaded`.

Дополнительно запускаются весь тестовый файл хронологии, frontend production build и точечный pre-commit для изменённых файлов.
