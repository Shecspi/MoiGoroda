# Кластеризация непосещённых городов на основной карте

## Цель

Устранить зависания основной карты посещённых городов при отображении более тысячи непосещённых городов, сохранив доступ к каждому городу и существующий сценарий отметки города посещённым.

Изменение применяется только к основной карте, реализованной в `frontend/js/entries/map_city.js` и `frontend/js/components/toolbar_actions.js`. Карты коллекций и остальные карты не входят в область задачи.

## Текущее ограничение

`ToolbarActions.addNotVisitedCitiesOnMap()` сразу создаёт и добавляет на карту отдельный Leaflet DOM-маркер для каждого непосещённого города. `addMarkerToMap()` также заранее строит popup и, когда список пользователей не передан, повторно вызывает `getUsersWhoVisitedCity()` для каждого маркера.

В результате браузер одновременно создаёт более тысячи SVG-маркеров, обработчиков и popup, а также выполняет повторные вычисления. Это блокирует главный поток и особенно заметно на мобильных устройствах.

## Решение

Использовать отдельный `L.MarkerClusterGroup` только для непосещённых городов:

- на дальнем масштабе показывать кластеры с количеством городов;
- при приближении автоматически раскрывать кластеры в отдельные красные маркеры;
- отключать кластеризацию на zoom `8` и выше через `disableClusteringAtZoom: 8`;
- на максимальном масштабе использовать стандартное spiderfy-поведение для близких маркеров;
- оставить посещённые города, города подписок и места обычными маркерами поверх кластерного слоя;
- сохранить текущий API непосещённых городов без изменений;
- добавлять маркеры пакетно через `addLayers()` с `chunkedLoading`, чтобы длительная подготовка не блокировала интерфейс;
- хранить соответствие `cityId -> marker` в `stateNotVisitedCities` для адресного удаления города;
- создавать содержимое popup непосещённого города только при первом открытии;
- передавать непосещённым городам пустой список пользователей и не вызывать для них `getUsersWhoVisitedCity()`.

Для реализации используется пакет `leaflet.markercluster`, совместимый с текущим Leaflet 1.9.4.

## Поток данных

1. Пользователь нажимает кнопку показа непосещённых городов.
2. Клиент один раз загружает текущим API список городов и сохраняет его в `notVisitedCities`.
3. Для каждого города создаётся лёгкий Leaflet-маркер без заранее построенного popup.
4. Маркеры одной пакетной операцией передаются в `MarkerClusterGroup`.
5. Кластерный слой добавляется на карту. Индикатор загрузки удаляется после завершения пакетной обработки.
6. При первом клике по отдельному маркеру для него создаётся и привязывается popup; последующие открытия используют готовый popup.
7. После отметки города посещённым его красный маркер удаляется через `MarkerClusterGroup.removeLayer(marker)` и из `stateNotVisitedCities`, после чего существующий сценарий создаёт обычный зелёный маркер.
8. При скрытии непосещённых городов с карты снимается кластерный слой целиком. Данные, маркеры и индекс сохраняются для быстрого повторного показа.
9. При обновлении городов подписок непосещённые маркеры добавляются и удаляются через кластерный слой, не напрямую через карту.

## Состояние и жизненный цикл

`ToolbarActions` владеет одним экземпляром кластерного слоя непосещённых городов. Слой создаётся при инициализации `ToolbarActions` или лениво перед первой загрузкой и повторно используется до ухода со страницы.

Состояния:

- список ещё не загружен: `notVisitedCities` пуст, слой не содержит маркеров;
- список загружен и скрыт: слой заполнен, но не добавлен на карту;
- список загружен и показан: слой добавлен на карту;
- город стал посещённым: его маркер удалён из слоя и индекса, данные города удалены из `notVisitedCities` либо исключаются при последующей пакетной синхронизации.

Кнопка считается активной только когда кластерный слой добавлен на карту. Повторное включение не делает новый API-запрос и не пересоздаёт маркеры.

## Ошибки

Если API-запрос завершается ошибкой:

- индикатор загрузки удаляется;
- кластерный слой не добавляется на карту;
- кнопка возвращается в неактивное состояние `show`;
- показывается существующее сообщение об ошибке;
- повторное нажатие запускает новый запрос.

Ошибка создания отдельного маркера не должна прерывать обработку остальных городов: некорректная запись пропускается и регистрируется в консоли с идентификатором города.

## Внешний вид

Кластеры должны визуально обозначать непосещённые города и показывать количество содержащихся точек. Их цветовая гамма должна соответствовать существующим красным маркерам. Отдельные маркеры сохраняют текущую иконку и popup без изменения пользовательских текстов и действий.

Полигон охвата маркеров при наведении на кластер не отображается. Он отключается штатной опцией `showCoverageOnHover: false`; раскрытие кластера по клику, zoom-to-bounds и spiderfy остаются без изменений.

## Проверка

Автоматические frontend-тесты должны подтверждать поведение, а не внешний вид:

- непосещённые маркеры добавляются в `MarkerClusterGroup`, а не напрямую на карту;
- кластерный слой настроен с `chunkedLoading` и получает маркеры через пакетный `addLayers()`;
- кластерный слой создаётся с `showCoverageOnHover: false`;
- кластерный слой создаётся с `disableClusteringAtZoom: 8`;
- повторное включение не загружает API и не создаёт маркеры заново;
- скрытие снимает кластерный слой целиком;
- отметка города посещённым удаляет его из кластера и создаёт посещённый маркер;
- popup непосещённого города строится при первом открытии и не строится повторно;
- для непосещённых городов не вычисляется список пользователей подписок;
- ошибка запроса удаляет индикатор загрузки и восстанавливает состояние кнопки.

После изменений выполняются:

- релевантные frontend unit-тесты;
- полный `npm test` в каталоге `frontend`;
- production-сборка `npm run build` в каталоге `frontend`;
- существующие backend-тесты API непосещённых городов, если затрагиваются связанные файлы.

Ручная проверка выполняется на полном наборе городов России в Chrome DevTools с мобильной эмуляцией и CPU throttling:

- на дальнем масштабе в DOM находятся кластеры, а не более тысячи отдельных маркеров;
- карта остаётся отзывчивой при перемещении и масштабировании;
- пакетная загрузка не создаёт одной многосекундной long task;
- приближение раскрывает отдельные города;
- popup открывается корректно;
- отметка города посещённым удаляет его из кластера и показывает зелёным маркером без перезагрузки;
- скрытие и повторный показ слоя не выполняют повторный запрос и заметное повторное построение.

Жёсткий временной порог не фиксируется в unit-тестах, поскольку он нестабилен на CI. Производительность подтверждается структурными тестами и ручным профилированием на полном наборе данных.

## Вне области задачи

- изменение API или серверная загрузка по видимой области карты;
- кластеризация посещённых городов, подписок, мест или маркеров на других картах;
- изменение дизайна popup и действий внутри него;
- виртуализация или переход с Leaflet на другой картографический движок.
